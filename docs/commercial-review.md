# 深海鱼市商业化发布评审

这轮评审以新玩家能理解目标、持续获得可预期的进展，以及运营方能监控和恢复服务作为发布标准。游戏中的鱼币、渔币、奖票和深海 FX 都属于虚拟玩法。

## 内容与流程

| 范围 | 原版主要问题 | 本轮处理 |
| --- | --- | --- |
| 登录与回归 | 入口缺少游戏主体，首次启动、回到存档和服务维护的提示分散 | 港口主视觉、清晰的登入及注册路径、玩家可见的维护公告 |
| 钓鱼与装备 | 鱼种和海域难辨认，入门钓竿不足以在后续海域顺利捕捞 | 六个海域有各自的场景，鱼获与装备有独立图稿，航路调查提供满足下一阶段需要的关键装备 |
| 海域与成长 | 主要路线依赖彩票产出的锁钥，连续未中奖时可能停滞 | 港湾、礁石、海沟和裂谷的调查按捕捞进度发放钥匙，保留解锁鱼币成本 |
| 潮汐商会 | 捕捞至兑换的关系不够直观，批量与单笔发卡有不同路径 | 展示鱼获、兑换内容和仓库空间，统一发卡结算 |
| 委托与收集 | 新手引导结束后缺少短目标，也无法查看鱼种收藏 | 航务委托提供日常目标，航海日志登记鱼种并显示栖息海域与捕捞次数 |
| 刮刮乐与彩票 | 标的、奖池、当前票券状态和兑领奖励难以扫读 | 分清待刮、待开奖、待领取和已入账状态，保留奖池预览和按期结算 |
| 深海 FX | 交易时段、报价与成交反馈需要更显眼 | 报价与涨跌图放在同一界面，展示时段与交易约束 |
| 无灯黑市与设备 | 解锁原因和设备成本难理解，盯盘机缺少下单和撤单入口 | 按功能组织收购、店铺、工作间和超级刮刮乐。关键设备有独立美术，盯盘机支持限价挂单、撤单和到期处理 |
| 设置与显示 | 窄屏导航与弹层容易遮挡操作，旧美术主题之间层级不一致 | 调整移动布局、交互焦点和字号，保持深色、浅色及无灯主题可辨认 |
| 管理台与服务 | 缺少维护模式、配置历史回滚和系统作业的健康反馈 | 从管理台发布维护说明和全服公告，查看配置版本、服务状态和玩家账号 |

场景、鱼种和物品都使用项目内的静态图。鱼种图鉴复用钓鱼与商会的图稿，获得、出售和收藏时可按同一轮廓辨认。道具状态、品质名称和数量继续由界面文字表达。

| 目录 | 资产 |

## 上线验收边界

在目标环境核对正式域名与 HTTPS、真实邮件投递、持久卷、备份恢复和监控告警。按实际并发和保存量压测 SQLite 单实例再设定开放规模。长线物资经济与新手流失需要基于玩家数据评估，当前参数通过可达性、守恒边界及回归验收。

盯盘机在玩家同步且处于交易时段时检查行情。它只整笔成交，余额、持仓和机器预付不足时继续等待。旧存档的鱼种图鉴可从保留鱼获和最近一次鱼获恢复记录。

本轮核对了 46 个素材映射和最终生产构建。在桌面和 390 像素宽度的浏览器中，用独立存档验收首航、海域切换、兑换、委托领取、合票、翻卡、鱼种登记、黑市、盯盘机挂单撤单和管理入口。配置回滚与维护模式由服务端回归覆盖。整合测试中的旧引导文案断言已按新版交互更新，相关定向复验通过。
